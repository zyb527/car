# 主车第一阶段：坐标巡航、自转、接近与绕行

> 历史阶段说明：本文记录最初不含无线前馈的阶段方案。当前方案已经加入
> 全状态无线速度前馈，文件范围与完成状态以 `完整双车跟随新方案.md` 为准。

## 当前方案基线

- 主车位于右侧，负责完整任务；当前确认的初始位姿为 `(23 cm, -45 cm, 90°)`。
- 辅助车位于左侧，仅使用侧视双红外闭环保持并排、同向和平行。
- 当前辅助车不接收无线速度前馈，因此主车第一阶段也不依赖无线链路。
- 车体系为 `+vx` 向右、`+vy` 向前、`+w` 俯视逆时针；世界航向从
  世界 `+X` 指向车头计算，逆时针为正。

## 已建立的主车层次

- `motor.py`：已调好的三轮速度闭环、限幅、S 曲线和看门狗。
- `odometry.py`：IMU 航向和世界坐标积分。
- `main_config.py`：主车动作的集中配置，未标定参数不散落到控制逻辑中。
- `control.py`：动作结果、角度归一化、限幅和通用 PID。
- `navigation.py`：世界坐标直线巡航与原地绝对航向转动。
- `approach.py`：前向目标像素与 ToF 联合接近。
- `orbit.py`：保持目标可见和定半径的顺/逆时针弧线绕行。

四个动作统一输出车体系 `(vx, vy, w)`。主循环每 20 ms 只应选择一个动作，
并只调用一次 `MotorSystem.move()`；动作报告 `failed=True` 时必须
`hard_stop()`，不能恢复上一周期命令。

## 动作约定

### 坐标巡航

路点格式：

```python
{"x": 100.0, "y": 50.0, "heading_deg": 90.0}
```

控制器沿“上一段起点 → 当前路点”的直线生成世界速度，同时用横向误差把车
拉回直线，再转换为车体系。到点后返回 `waypoint_reached`，由状态机先调用
自转控制器；转向完成后再 `advance()`，避免同一周期既换路点又继续运动。

`PATROL_WAYPOINTS` 当前故意为空，防止代码烧录后上电即运动。应在确认场地
坐标、巡航方向和主摄视野后填写。

### 原地自转

输入世界绝对目标航向。采用快、中、慢三级角速度，并同时满足角度误差、
IMU 角速度和稳定时间后才报告完成。

### approach

输入前向摄像头的 `found/x/y/class_id` 和 ToF 距离。目标横向像素误差同时
产生小幅侧移和偏航修正，前进速度由 ToF 距离曲线和图像纵向慢速曲线共同
约束。只有目标像素和 ToF 距离同时到位才完成；目标或必需的 ToF 丢失时
返回失败并要求硬停车。

### orbit

开始时指定相对绕行角或世界绝对目标航向，以及顺/逆时针方向。切向速度和
角速度满足 `vx = w × 旋转半径` 的基本关系；ToF 控制径向距离，视觉横向
误差修正目标朝向。航向跨越 `±180°` 时使用增量累计，不会误判绕行进度。

## 主车后续仍需补齐

1. 前向 OpenART 八字段组合帧接收、校验、目标锁定和超时停车。
2. ToF 非阻塞接收与新鲜度检查。
3. 顶层状态机：巡航 → 搜索/自转 → approach → orbit → 推行。
4. 推行、障碍处理、黄线停车与坐标校正。
5. 统一故障管理、调试遥测和板端入口 `main.py`。
6. 最后再决定是否加入主车到辅助车的无线前馈；它不是当前四个动作的依赖。

## 首次实车顺序

1. 桌面测试和语法检查。
2. 架空验证自转正方向以及世界/车体坐标转换。
3. 地面低速跑单条坐标直线，再跑直角路点。
4. 静止读取目标像素和 ToF，标定 approach 目标点。
5. 低角速度执行 20°～30° orbit，确认 `vx/w` 同号关系和 ToF 径向符号。
6. 四个动作稳定后才接顶层状态机。
