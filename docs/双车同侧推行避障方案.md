# 双车同侧推行避障方案

## 1. 目标与边界

当前两车位于物体同一侧、车身保持平行，物体位于两车中间前方。主车
负责识别目标物体和障碍、规划推行方向并发送无线速度前馈；辅助车不使用
自己的障碍数据，只按现有“主车前馈 + 刚体槽位解算 + 视觉队形修正”跟随。

本方案只在避障后恢复原推行航向，不回到避障前的原中心线。避障结束后，
编队在横向偏移后的平行轨迹上继续推行。

摄像头继续使用八字段协议：

```text
target_found,target_x,target_y,target_id,
hazard_found,hazard_x,hazard_y,hazard_type
```

- `hazard_type=1`：障碍。
- `hazard_type=2`：黄线，继续交给原推行结束逻辑。
- 梯形危险区由摄像头端判断；只有障碍进入梯形框，才发送
  `hazard_found=1`。
- 主控不能把串口超时当成 `hazard_found=0`。只有收到新鲜、格式正确的
  八字段帧，并且其中明确为 `hazard_found=0`，才能累计离障时间。

## 2. 为什么不能照搬 car141929

`car141929` 的旧推行避障以两车相向/前后配合为前提，领导车根据障碍
左右位置直接把目标航向改成原航向加减约 45 度，另一辆车再根据无线状态
作相反方向处理。

当前结构中两车位于同一侧共同推物体。如果只给两车相同的前进速度和
角速度：

- 转弯外侧车需要走得更快，但实际得不到速度差；
- 两个推杆接触点会沿物体表面相互剪切；
- 物体可能向一侧旋出，或其中一辆车失去接触；
- 主车中心的旋转命令不能保证物体中心沿期望避障方向运动。

因此必须先生成“物体参考点”的运动，再解算主车和辅助车各自需要的
刚体速度。

## 3. 已知机械参数

```text
两车旋转中心间距 B = 20 cm
物体中心在两车中心连线前方 L = 10 cm
单车宽度约 20 cm
物体宽度约 5~10 cm
单个推杆宽度约 10 cm
推杆与物体为平面接触
```

坐标沿用当前底盘定义：

```text
x：车体向右为正
y：车体向前为正
w：逆时针为正
```

主车位于右侧，辅助车位于左侧。以两车中心连线中点为编队中心，则：

```text
主车位置     r_main     = (+B/2, 0)
辅助车位置   r_follower = (-B/2, 0)
物体位置     r_object   = (0, L)
```

## 4. 物体参考点刚体解算

控制器先计算物体中心希望得到的速度：

```text
V_object = (Vox, Voy)
编队角速度 = w
```

然后将其转换为两车速度：

```text
主车：
Vmx = Vox + w * L
Vmy = Voy + w * B/2
Wm  = w

辅助车：
Vfx = Vox + w * L
Vfy = Voy - w * B/2
Wf  = w
```

代入当前尺寸：

```text
Vmx = Vox + 10w
Vmy = Voy + 10w

Vfx = Vox + 10w
Vfy = Voy - 10w
```

其中速度单位为 cm/s，`w` 单位为 rad/s。

这组解算有两个作用：

1. 两车转向时共同产生 `wL` 横移，转动中心靠近物体，减少推杆在物体
   背面的横向刮动。
2. 两车前进速度相差 `wB`，外侧车快、内侧车慢，保持两个接触点的刚体
   几何关系。

当前辅助车已经按以下关系处理主车前馈：

```text
V_follower = V_main + w × r_follower_from_main
```

其中 `FORMATION_RIGHT_OFFSET_CM=-20`、`FORMATION_FORWARD_OFFSET_CM=0`。
因此无线协议无需改成“两套速度”。主车只需：

1. 在 `push.py` 内按物体参考点算出 `(Vmx, Vmy, w)`；
2. 主车执行这条命令；
3. 继续发送主车实际限幅后的 `(Vmx, Vmy, w)`；
4. 辅助车用现有槽位补偿自动得到 `(Vfx, Vfy, w)`。

为了避免主车限幅后破坏刚体比例，推行避障控制器必须在发送给电机前，
同时检查主车和辅助车的预测速度。任一车辆将超限时，应同比缩小
`V_object` 和 `w`，不能依赖两块主控板分别截断。

## 5. 障碍方向选择

首次收到 `hazard_type=1` 且 `hazard_found=1` 时锁定避障方向：

```text
hazard_x < AVOID_CENTER_X：障碍偏左，向右避让，偏角为负
hazard_x > AVOID_CENTER_X：障碍偏右，向左避让，偏角为正
```

一次避障过程中不允许根据后续 `hazard_x` 反复换边。否则障碍在画面中心
附近抖动时，两车和物体会左右摆动。

`AVOID_CENTER_X` 初始可使用当前目标中心 `160 px`，但应保留为独立标定
参数，因为主摄安装点在主车而不是两车编队中点。

当 `hazard_x` 位于中心死区时，使用固定的 `PREFERRED_AVOID_DIRECTION`。
第一版固定为向左避让。

## 6. hazard_y 三档偏角与速度

`hazard_y` 越大表示障碍越近。按当前要求使用三档目标偏角：

| 障碍像素 Y | 相对原航向偏角 | 初始推行速度比例 |
|---|---:|---:|
| `y < 30` | `20°` | `75%` |
| `30 ≤ y < 60` | `45°` | `50%` |
| `y ≥ 60` | `60°` | `30%` |

以上速度比例作为第一版确认值，之后再根据低速实车结果标定。基础推行速度、目标像素 X/Y 修正
和 ToF 接触距离修正先组合成 `Voy`，再乘当前避障速度比例。

档位切换不能直接跳变到电机命令：

- 偏角档位可以离散选择，但目标航向必须经过角度斜坡；
- `w` 使用限幅和角加速度限制；
- `Vox/Voy` 使用现有 S 曲线或独立加减速限制；
- 30 px、60 px 边界加入像素回差，避免连续跨档；
- 升级到更近档位立即生效，退回更远档位需要连续稳定若干帧。

建议第一版回差：

```text
30 px 边界回差：±3 px
60 px 边界回差：±5 px
```

第一版暂不设置基于 `hazard_y` 的独立紧急停车阈值。最大档保持 60° 偏角
和 30% 推行速度；后续若实车验证仍存在来不及避让的情况，再增加该阈值。

## 7. 状态机

```text
PUSH_NORMAL
  └─ 新鲜帧 hazard_found=1, hazard_type=1
       ↓
AVOID_ENTER
  ├─ 锁定原推行航向 original_heading
  ├─ 根据首次稳定 hazard_x 锁定避障方向
  └─ 初始化角度/速度斜坡
       ↓
AVOID_TRACK
  ├─ 根据 hazard_y 选择 20°/45°/60°档位
  ├─ 只允许档位和减速程度变化，不允许避障方向翻转
  ├─ 持续进行物体像素、ToF接触和刚体速度闭环
  └─ 新鲜帧明确 hazard_found=0
       ↓
AVOID_CLEAR_HOLD
  ├─ 保持最后一个避障偏角
  ├─ 保持最后一个减速档位
  ├─ 连续等待 500 ms
  ├─ 期间再次 found=1：立即回 AVOID_TRACK
  └─ 500 ms 内摄像头数据过期：安全停车，不得当作离障
       ↓
AVOID_RETURN
  ├─ 将目标航向平滑回到 original_heading
  ├─ 不回原中心线
  ├─ 返回过程中继续物体像素/ToF接触闭环
  └─ 航向误差稳定进入允许范围
       ↓
PUSH_NORMAL
```

`AVOID_CLEAR_HOLD` 的 500 ms 从第一帧新鲜的 `hazard_found=0` 开始累计，
不是从最后一次接收到障碍帧开始累计。

## 8. 目标物体闭环在避障期间的处理

目标和障碍在同一八字段帧内，可以同时有效。因此避障时仍保留：

- `target_x`：修正物体相对两推杆中点的横向位置；
- `target_y`：修正推杆与物体的前后接触位置；
- ToF：修正主车推杆接触距离；
- 主车航向：跟踪 `original_heading + signed_avoid_angle`。

这些修正必须先作用于物体参考速度 `(Vox, Voy)`，再做两车刚体解算。
不能在完成解算后只给主车叠加视觉修正，否则辅助车不会获得相同的编队
平移，两个接触点会失配。

由于辅助车暂时没有物体接触传感器，它只根据主车的速度前馈和红外队形
视觉保持与主车的相对位置。辅助车视觉修正仍保留，但避障转向时必须限制
修正量，避免覆盖刚体解算产生的 `wB` 速度差。

## 9. 协议与新鲜度规则

主摄必须持续发送完整八字段帧，包括未发现障碍的帧：

```text
1,160,170,2,1,145,52,1
1,160,170,2,0,0,0,0
```

控制器分别维护：

```text
last_camera_frame_ms
last_hazard_seen_ms
hazard_clear_start_ms
```

判断顺序：

1. 帧格式错误或摄像头超时：停车或保持安全状态。
2. 新鲜帧 `hazard_type=2`：执行黄线逻辑。
3. 新鲜帧 `hazard_type=1`：进入/维持避障。
4. 新鲜帧 `hazard_found=0`：进入/维持 500 ms 离障确认。

摄像头端继续负责梯形框判断，主控不复制梯形边界公式，避免两端阈值不一致。

## 11. 测试与实车标定顺序

### 桌面测试

1. 三个 `hazard_y` 区间选择正确角度和速度档位。
2. 障碍在左右两侧时选择相反方向，且一次避障中方向不翻转。
3. `hazard_found=0` 不满 500 ms 不返回。
4. clear 期间重新发现障碍，回到避障跟踪状态。
5. 摄像头超时不能被当作障碍清除。
6. 主车和辅助车解算速度满足刚体关系。
7. 任一车辆预计超限时，两车命令同比缩放。
8. 返回阶段只恢复原航向，不恢复原路径。
9. 黄线事件优先于普通障碍避让并能正常结束推行。

### 实车标定

1. 架空验证两车在 `w>0` 和 `w<0` 时的前进速度差方向。
2. 不放物体，低速验证两车保持 20 cm 平行槽位转向。
3. 放置物体，以 20°、低速档验证两个推杆是否持续平面接触。
4. 依次验证 45°、60°，测量目标像素和 ToF 接触误差。
5. 标定三档速度比例、`w` 限制和紧急停车像素。
6. 最后加入静态障碍，验证 500 ms clear hold 和恢复原航向。
