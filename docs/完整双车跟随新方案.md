# 完整双车跟随新方案与文件清单

## 方案基线

主车执行 `car141929` 的完整任务链：坐标巡航、搜索、approach、orbit、
推行、避障、黄线/坐标校正和回库。辅助车不再执行独立目标任务，而是在
主车左侧使用“主车无线速度前馈 + 侧视双红外视觉修正”保持并排、同向。

主车所有运动状态都发送经过底盘 S 曲线后的 `(vx, vy, w)`：

```text
follower_vx = main_vx + visual_trim_vx
follower_vy = main_vy + visual_trim_vy
follower_w  = main_w  + visual_trim_w
```

## 主车主控板

最终板端文件：

```text
main.py                    顶层任务状态机和唯一主循环
main_config.py             car141929 动作参数及当前底盘比例换算
control.py                 PID、MotionStep、限幅和角度工具
motor.py                   三轮运动学、轮速PI、前馈、S曲线和看门狗
odometry.py                IMU航向和世界坐标里程计
navigation.py              waypoint直线巡航和原地转向
approach.py                car141929 接近、丢失衰减和绕行交接逻辑
orbit.py                   car141929 绕行、最终对准和贴靠逻辑
vision.py                  主摄组合帧接收、目标锁定和超时处理
tof.py                     ToF非阻塞接收和新鲜度检查
push.py                    car141929 推行、目标保持、障碍和黄线处理
garage.py                  car141929 回库流程
wireless_feedforward.py    全状态速度前馈发送
```

主车板端清单现已齐全：`main.py` 负责唯一主循环和完整任务状态机，
`garage.py` 已适配为八字段协议下的非阻塞回库控制器。六方向命令表仅保留
给桌面方向/协议回归测试，正式入口不再执行动态跟随测试序列。

当前 `PATROL_WAYPOINTS` 仍按确认保持为空，初始位姿为
`(23 cm, -45 cm, 90°)`。空路径上电后只在收到新鲜八字段主摄帧时原地搜索，
主摄未上线时保持硬停止。主摄程序本身尚待后续编写。

`car141929/assist.py` 的“两辆车分别执行任务/互相召唤”不进入新方案，
因为新辅助车只负责跟随；这属于跟随方案本身明确替换的旧双车职责。

## 主车前向摄像头

目录 `maincam/` 最终保留：

```text
main.py
object_detectors.py
model_object_detectors.py
cmm_load.py
cmm_cfg.csv
labels.txt
find_apriltag.py
garage.py
```

输出统一组合帧：

```text
target_found,target_x,target_y,target_id,
hazard_found,hazard_x,hazard_y,hazard_type
```

其中 `hazard_type=1` 为障碍，`hazard_type=2` 为黄线。

## 辅助车主控板

目录 `car/辅助车/`：

```text
main.py
config.py
follow.py
motor.py
odometry.py
wireless_feedforward.py
```

辅助车将主车新鲜无线前馈作为基础运动，视觉只负责队形误差修正。视觉
暂时丢失时继续执行纯前馈；无线前馈超过 300 ms 且视觉也不可用时硬停。

## 辅助车侧视跟随摄像头

目录 `car/跟随摄像头/`：

```text
main.py
config.py
ir_tracker.py
```

摄像头识别主车侧面的两个红外灯，并发送：

```text
x_cm,y_cm,theta_deg
```
