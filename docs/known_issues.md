# 已确认问题记录

本文记录旧工程和 `car_follow_last` 中已经确认、在新工程中不得原样继承的问题。

## 双车跟随链路

1. 跟随摄像头输出 `mid_x,mid_y,line_angle,distance,quality`，但跟随控制器读取不存在的 `error_x,error_y,angle_error_deg`，看到红外点后会触发 `KeyError`。
2. 新跟随车只发送启动 READY，主车旧状态机却仍在推行前等待对方状态 14/5，流程会卡死。
3. 主循环发送带 `vx,vy,w` 的新无线帧，旧状态处理函数仍发送默认速度为零的兼容帧，可能覆盖有效前馈。
4. 无线协议缺少 CRC、序号、发送者、运行模式和明确的 STOP/ESTOP 标志，也没有持续字节流缓存。
5. 无线过期后 IR-only 可以无限运行；跟随循环异常时没有统一的电机急停兜底。
6. 红外点距、质量和多项标定配置没有进入实际控制，READY 判定也没有检查两车间距。

## 主摄像头

1. 新障碍检测阈值覆盖红、蓝、绿、棕目标颜色，可能把任务目标本身识别成障碍。
2. 组合帧只允许一个 hazard，黄线和障碍会互相遮蔽。
3. 旧主摄中已经调过的白平衡、亮度、目标锁定、连续命中和丢失防抖没有完整保留。
4. 单帧目标丢失即可令车控退出接近状态，容易产生状态抖动。

## 新工程约束

1. 每个控制周期只能产生一次最终底盘指令和一次无线运行帧。
2. 跟随车必须具有 `DISARMED / ALIGNING / READY / FOLLOWING / DEGRADED / STOP` 等明确模式。
3. 任何异常、命令超时或急停都必须直接清零 PWM，并重置速度闭环和运动规划器。
4. 主车、跟随车、主摄和跟随摄像头分别打包，不能把桌面缓存和无关测试脚本部署到板端。
